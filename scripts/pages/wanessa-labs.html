Agentic Genesis

How Clembot Evolved from Internal Tooling

Clembot was not conceived as a single prompt or weekend script. It was forged through 7 months of real product iteration inside Wanessa Labs' internal tooling track:

Phase 01 · Local-First Foundations

Local Clembot LLM

The journey began by building an Ollama adapter that routes agent harness calls to a local LLaMA 3 model, cutting session costs and keeping sensitive client context off the public cloud.

Stack: Ollama · LLaMA 3 · TypeScript · Production

Phase 02 · Team Orchestration

Clembot Slack & Notion Sync

Clembot split into specialized functional subagents (Marketing, Product, Sales) that post their activities to Slack channels automatically while Notion databases track gathered market signals.

Stack: Claude Code · Slack API · Notion SDK

Phase 03 · State & Optimization

Memory with Events & Token Thrift

To avoid agent amnesia between runs, Wanessa Labs engineered event-driven state synchronization and Token Thrift—a schema minimization layer that prunes unused parameters and prevents context window starvation.

Stack: Event Ledger · Token Thrift · Gauntlet Loop

Phase 04 · Native Desktop Voice

Clembot-dictate (v1.0 → v1.3.0)

Shipped a standalone Windows desktop app with a dedicated sidecar client for offline voice dictation and clipboard cleanup, evolving through 4 major releases to add safe clipboard undo and entry categorization.

Stack: Sidecar Client · Local Whisper · Python / C#

Phase 05 · The Vulnerability Spike

27 Subagents & Commercial Injection

As Clembot expanded across 5 divisions (Orchestration, Content, Research, Design, Engineering), the Design Director subagent was given 15 third-party MCP tools. An untrusted provider (WebZum) injected commercial steering prompts, corrupting agent responses.

Finding: Prompt Injection · 87% Token Waste · Rogue Upgrades

Phase 06 · The Inflow Gate

Clembot Doorman & Bazantic

Wanessa Labs engineered Clembot Doorman: an offline bash hook (mcp-gate.sh) failing closed in < 5ms, analyzing prompt history (doorman needs), and compiling pinned Bazantic Markdown recipes (recipe.md) via Bazantic.com.

Result: Zero-Trust Security Gate · ETHOnline 2026 · 428 Tests

Engineering Tenets

How Wanessa Labs Builds Software

Our core principles distinguish Wanessa Labs products from standard AI wrappers:

Tenet 01

Depth Over Flash

We reject the generic AI aesthetic—no neon gradients, no exaggerated drop shadows, and no floating cards with zero substance. We design interfaces with tactile border depth, intentional typographic rhythm (Bricolage Grotesque, Archivo, Barlow Condensed), and physical paper/ink contrast.

Tenet 02

Zero-Trust Local First

A security gate that relies on an external server is vulnerable the moment the network drops. Our security hook runs locally in Bash with zero dependencies in under 5ms, failing closed before a single byte leaves the machine.

Tenet 03

Append-Only Decision Logs

We never invent grades or claim capabilities we have not implemented. If a layer didn't run, we state it as unmeasured rather than 0. Every claim resolves to a verifiable transcript tape, and our entire 283-update decision log is public.

Tenet 04

Deterministic Continuity via Recipes

Agents suffer from drift and hallucination across turns. By synthesizing pinned Bazantic recipes, we reduce schema token bloat by 87% and guarantee deterministic invocation arguments.
