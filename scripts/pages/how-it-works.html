Architecture & Defense Funnel

How Clembot Doorman Protects Autonomous Agents

A sequential, cost-bounded architecture designed to protect agent context windows. Clembot Doorman stops redundant or unsafe tools locally for $0.00, only advancing to remote adversarial grading on Base for $0.01 when a candidate is genuinely novel.

Sequential Defense Pipeline

The 2-Phase Defense Funnel

Every candidate MCP tool passes through two sequential stages before entering an agent's allowlist:

Phase 1 · Local Pre-Screening $0.00 LOCAL

Zero network calls and zero model tokens. Free static inspection directly on your machine.

1
doorman doctor Inspect Build

Reads local harnesses (Claude Code, Cursor, Gemini), active MCP servers, and agent-to-tool exposure ratios in plain text.

2
doorman needs Prompt History Analysis

Analyzes session JSONL prompt transcripts to identify genuine capability gaps, matching against pre-vetted tools.

3
Local Fit Review Stop Redundancy

Compares candidate schemas against existing skills. If an existing skill already handles the task, adoption halts at $0.00.

4
Local Gate (mcp-gate.sh) < 5ms · Exit 2

PreToolUse hook intercepts tool calls before LLM context. Unapproved or rogue tools are blocked instantly offline.

Phase 2 · Verified Gateway $0.01 BASE

Adversarial evaluation and continuous protection triggered only when novelty is proven.

5
x402 Micropayment Permit Base USDC

Negotiates HTTP 402 Payment Required on Base with signed EIP-712 permits and bounded caps ($1/run, $5/day).

6
100-Pt Adversarial Audit Scorecard Probes

Adversarially probes candidate tools for indirect prompt injection, credential leaks, and parameter hallucination.

7
Pinned Bazantic Recipe Deterministic

Generates pinned, minimal recipe.md schemas, reducing token bloat by 87% (3,400 to 420 tokens).

8
Allowlist & Vault Log Ready for Production

Appends approved checksum to registry/allowlist.json and archives audit tape in ClemVault.

Layer Breakdown

Four Layers, One Offline Gate

How the components work in harmony:

Layer 0

The Doctor (Harness Inspection)

Zero-dependency static scanner. Reads CLAUDE.md, settings.json, .mcp.json, and agent configurations. Reports what an agent in the current project can currently reach without executing any code. 

doorman doctor
Layer 1

Needs Recommender (Prompt History)

Parses Claude Code transcript JSONL logs to detect what capabilities your agents struggled with or explicitly requested (e.g., browser automation, cloud deployment, payments), recommending pre-graded, safe MCP servers. 

doorman needs
Layer 2

The Gate (PreToolUse Security Hook)

A 180-line offline Bash script wired into Claude Code's PreToolUse event. Intercepts all mcp__.* calls, verifying tool names against registry/allowlist.json. If unreviewed, exits 2 in < 5ms, protecting the context window. 

.claude/hooks/mcp-gate.sh
Layer 3

Scorecard & Bazantic Gateway

Autonomous evaluation gateway. Coordinates Base x402 micropayments ($0.01 USDC), runs adversarial probes, and publishes pinned recipe.md definitions to eliminate multi-turn hallucination. 

clembot-doorman.bazgateway.com
