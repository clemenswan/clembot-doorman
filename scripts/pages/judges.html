Core Evaluation

The Five ETHGlobal Judging Categories

How Clembot Doorman delivers against the five dimensions evaluated by ETHGlobal judges:

01 · Technicality

Sophistication & Architectural Rigor

The Problem: Adding an MCP server takes one line of JSON. After that, an unvetted third-party server injects tool descriptions directly into the agent's LLM context window, enabling covert prompt injection, schema bloat, and unauthorized execution.

Our Solution:

  • Offline Security Hook: A 180-line standalone Bash hook (mcp-gate.sh) executing in < 5ms with zero external runtime dependencies. Fails closed (exit 2).
  • Dual-Sandbox Harness Adapter: Isolates execution in local Docker containers, driving Claude Code via native CLI flags without credential leakage.
  • EIP-712 x402 Micropayments: Protocol-level HTTP 402 challenge negotiation on Base USDC with bounded spend caps ($1/run, $5/day).
  • Deterministic Schema Synthesis: Prunes bloated MCP schemas from 3,400 tokens down to 420 tokens in pinned recipe.md files.

Verified in: src/vet.mjs · bin/mcp-gate.sh · src/budget.mjs

02 · Originality

First Package Manager & Gate for Agent Tools

Fresh Problem Space: While traditional web applications have firewalls and package managers (npm, brew), AI agents have zero adoption gates—anyone who pastes an MCP URL grants arbitrary external code full prompt influence.

Creative Inventions:

  • Discovery of Stealth Steering: Uncovered real-world covert ads embedded in MCP servers (WebZum's 6,290-character injection instructing models to recite sales scripts and de-rank competitors).
  • 2-Phase Defense Funnel: Eliminates redundant or unsafe tools locally for $0.00, only paying $0.01 for remote adversarial grading when a tool is proven novel.
  • Reverse-Needs Recommender: Inspects actual session history (doorman needs) to suggest tools based on what subagents actually asked for.

First reported in: site/index.html (#finding) · evals/fixtures

03 · Practicality

100% Production Ready & Battle-Tested

Not a Mock or Concept: Clembot Doorman is fully implemented, fully tested, and already running in active production.

  • Complete Test Coverage: 465 unit tests and 40 CLI tests passing with zero failures.
  • Real-World Deployment: Guards the active 27-agent roster of Clembot, a multi-client marketing agency.
  • 24 Public Audits: Scanned and graded 24 real third-party MCP servers, publishing reproducible transcript tapes for every single score.
  • Live Infrastructure: Deployed on Cloudflare Pages production with custom domain (clembot-doorman.wanessalabs.com) and Bazantic Gateway (clembot-doorman.bazgateway.com).

Run suite: npm test · 465 unit passed, 40 CLI passed

Developer & Agent Ergonomics:

Settlement

Two payments settled on Base. One delivered.

Both are real transactions on Base mainnet and both are yours to check. The second one is the more useful evidence, because it bought nothing and the service could not tell.

Base mainnet · 13 September 2026
0xf1d7aa9696c92b012c8f1eebd222d353c0e452e264294145fb7825000e2d01a0
  USDC 0.01   block 51242088   audit 8ff6bba8   grade A 91.36, delivered in 40s

0x2748fc43c34d632d1a88c0bce25ace12b0a93dc477cb2676bd2717416a5b045f
  USDC 0.01                    audit 11364ba2   FAILED, no grade published

The second audit hit a model rate limit mid-probe. The runner refused to publish a partial grade, which is correct and is the behaviour this whole project argues for. The buyer still paid. Three things follow, and none of them is a bug in the code:

The money settles before the work, at enqueue

POST /grade answers 202 when the audit joins the queue. The gateway settles against that 202. Grading happens minutes later on a probe runner the gateway never hears from, because a Cloudflare Worker cannot spawn a process and the static layer shells out to Python. Charging at enqueue was never an examined decision. It was a default that no money had ever run through until 13 September.

The gateway forwards no evidence that payment happened

Measured, not assumed. A paid request reaches the origin carrying 29 headers and not one of them concerns payment: proxy plumbing, cf-*, fly-*, x-forwarded-*, and the configured credential. No payment-response, no x-payment, nothing x402.

This is a property of the gateway pattern rather than a defect in anyone’s implementation. x402 v2 standardises what the client sends and what the resource returns, and says nothing about what a gateway tells the API behind it.

So the service cannot tell that it owes a refund

It cannot count its own revenue either. /api/ledger reports spent: 0 after two real payments, and that number is honest rather than broken: the origin has no way to know. Rather than leave a counter that reads zero and looks like an answer, every authorised call now writes a paid_unaccounted row naming the headers that did arrive. The gap is recorded instead of silent.

Closing it properly needs three changes, all of them out of scope for a hackathon weekend: charge on delivery rather than on enqueue, forward a settlement receipt upstream, and give the runner a model budget that cannot exhaust mid-audit.

Disclosure: payer and payee are the same address

The grant paying and the gateway receiving both resolve to 0x72Bb…586D, so these transfers prove the mechanism end to end rather than a third-party sale. Every step is real, including on-chain settlement. The counterparty is not. Said here rather than left on Basescan for someone to find.

Verification FAQ

Judge Frequently Asked Questions

Where are the live 24-server audit tapes and evidence hashes?

Every grade on the 24-server board (e.g. https://clembot-doorman.wanessalabs.com/#audits) links directly to an immutable, replayable transcript tape on scorecard.wanessalabs.com/grade/{audit_id}/transcripts with a verifiable SHA-256 evidence hash. Zero grades are estimated or mocked.

How does the live x402 Base mainnet gateway challenge return 402?

Send an unauthenticated POST to https://clembot-doorman.bazgateway.com/grade. The response returns an HTTP 402 with base64 PAYMENT-REQUIRED header detailing Base network (eip155:8453), USDC token contract address (0x8335...2913), and exact price (10,000 atomic units = $0.01 USDC).

Where are the three Bazantic platform recipes committed?

The three 8-field JSON recipes are located in bazantic/recipes/: 01-vet-mcp-candidate.json (Agentify an API), 02-deepwiki-pinned-researcher.json (Continuity), and 03-governance-pipeline.json (Multi-API Workflow).
