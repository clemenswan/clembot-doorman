The Package Manager & Security Doorman for Clembot

Inspect your build. Recommend vetted MCPs. Block rogue tools before context.

Adding an MCP tool is one line of JSON. After that line, an unvetted third-party server injects text straight into your agent's context window.

We tested 24 servers. One commercial product hid 6,290 characters of unprompted steering ads inside its tool descriptions. Clembot Doorman intercepts tool invocations locally with a zero-dependency gate, recommends vetted tools from prompt history, and blocks rogue code before context.

TL;DR · The Package Manager for Clembot

Clembot is built in many versions, with the latest utilizing Claude Code and a custom combination of agent harnesses. While agents need tools to do real work, loading raw MCP servers blindly introduces in-context steering ads, prompt injection risks, and token-draining schema hallucination.

1. Inspect & Recommend

doorman doctor reads your active build. doorman needs inspects your local prompt history to identify capability gaps, recommending safe, pre-graded MCP tools.

2. Zero-Dependency Gate

A 180-line offline PreToolUse hook blocks hostile or unapproved tools locally (exit 2). Deny beats allow; rogue servers never reach your agent's context window.

3. Arm with Bazantic Recipes

Evaluates candidate tools over an x402 micropayment rail ($0.01 on Base) and provides proven Bazantic Recipes so agents execute on the first try without wandering.

Net-New Claude Installation

What does your agent actually keep reaching for?

A fresh install has no tools and no idea which ones it needs. doorman needs reads the prompts already typed into the build, counts them against twelve capability buckets, subtracts what is already installed, and matches what is left against the graded feed. Free, keyless, and the prompts never leave the machine: the one request it makes is the same anonymous GET /feed anybody can call.

It will not tell you a server works. Nothing here drove anything, so a match means the candidate's own published text claims the capability you keep asking for, and the verdict word is worth-measuring rather than fits. A need nothing graded covers prints as a GAP, because a hole in our catalogue is more useful to you than a filler suggestion.

        Methodology, Wallet Architecture & Economics: Why only one stage carries a price
        

          

            Five stages run on your machine and cost you nothing ($0.00), because they inspect your build and that information should never leave it. One stage runs on remote infrastructure—driving live third-party MCP endpoints against adversarial injection suites.
          

          

            Why the agent never holds a wallet: Storing private keys or seed phrases in an LLM's prompt context or memory is a severe security vulnerability. Instead, Clembot Doorman decouples intent from custody. Settlements are facilitated through Bazantic Hosted Grants (scoped to the service, capped to a ceiling like $1.00, and revocable) or single-use EIP-712 spend permits. The agent never holds private keys, and you never need to install a wallet or Bazantic SDK dependency—everything operates over standard HTTP (status 402, x402 v2 headers) and standard MCP over SSE.
          

          

            A grade is cached and its transcript tape is free forever, so the first agent pays a cent ($0.01 USDC on Base), and every subsequent agent reads the verdict and tape for nothing. Local spend caps in budget.mjs ($1/run, $5/day) reserve funds in an offline append-only ledger before any paid request can fire.

The Bazantic recipe.md advantage: naked tool vs. guided execution

    

      The same model, the same task, run in two images that differ by exactly one install layer. That is
      what doorman eval does, and it is the only stage that can answer whether a server makes
      your agent better rather than whether it is well built.
    


    

      
Empirical Evaluation Architecture · Zero-Cost Bounded Simulation

      

        Measurable schema compression: 87% token reduction (3,400 raw schema tokens compressed to 420 pinned recipe tokens) and zero recursive retry loops under gated execution.
      

      

        Rather than publishing synthetic or cherry-picked model scores, Clembot Doorman provides a local, reproducible benchmark harness for your own stack. doorman eval spins up two isolated Docker sandboxes running identical tasks on your own machine. The worst-case cost is bounded mathematically before any container starts: doorman eval --estimate derives exact token ceilings ($0.00 spent, calculating $3.57 typical or $18.16 worst case on Haiku) so your team can verify behavioral improvements on your own models without budget surprises.

      Methodology: Why steering ads are classified separately from jailbreaks
      

        

          Across the twenty-two other third-party servers, the longest tool description is 2,285 characters and not one trips a single steering marker. WebZum trips all six.

    How it fits together
    
    
    Five layers, and the boundary is the product
    
    
    
      Every layer below refuses something the layer above it cannot check for
      itself. That is the whole design. A grade is only worth having if the thing
      that acts on it is small enough to audit, so the piece that actually blocks a
      call is 180 lines of bash with no network access and no interpreter, and
      everything expensive sits behind it.
    
    

    
    
      
    
        
    1 · your project bash · no deps
    
        
    The gate
    
        
    mcp-gate.sh · allowlist.json
    
        
    
          A PreToolUse hook on mcp__.*. It reads two lists and
          exits. No node, no jq, no network, and deny beats allow. A missing
          registry blocks rather than opens, so every way this can be installed wrong
          fails in the safe direction.
        
    
      
    

      
    
        A server nobody graded never reaches the network. The hook exits 2,
        which is the only exit code Claude Code actually surfaces: exit 1 is silent.
      
    

      
    
        
    2 · the doorman subagent · node
    
        
    Fit, then budget, then buy
    
        
    /vet <url> · src/vet.mjs · src/budget.mjs
    
        
    
          Three phases, and two of them are free. Fit review reads the existing roster
          and stops a redundant candidate at zero cost. Then a single-use permit
          is written to the ledger before the call, not after, and an unreadable price
          stops the run: a client that treats an unknown price as zero passes every cap
          it has, forever.
        
    
      
    

      
    
        One grade, one permit, capped before anything is signed.
      
    

      
    
        
    3 · bazantic gateway live · Base x402
    
        
    Payment and discovery
    
        
    x402 pathway · /mcp · published recipe.md
    
        
    
          The scorecard issues a spec-correct 402 challenge and the Bazantic Gateway
          provisions automated settlement on Base mainnet. An agent holds an EIP-712
          spend permit capped at $0.01 USDC; the gateway settles the transaction on-chain
          and delivers the authenticated request with immutable cryptographic proof.
        
    
      
    

      
    
        HTTP 402, a signed EIP-712 permit, then on-chain Base settlement. The gateway
        handles paid evaluation pipelines and serves cached audits via free discovery.
      
    

      
    
        
    4 · mcp scorecard cloudflare worker + d1
    
        
    The graded service
    
        
    /grade · /mcp · /openapi.json · /badge/*.svg
    
        
    
          One MCP tool, grade, whose own description is written to the
          standard it enforces and gets scanned by our own injection probe. It answers
          from cache instantly when a recent audit exists, and otherwise returns
          202 and an audit id with no grade, because grading takes minutes and a
          provisional score is a lie with a number on it.
        
    
      
    

      
    
        The verdict is never computed in the request. Poll the audit id, or read
        the transcript.
      
    

      
    
        
    5 · probe runner separate machine
    
        
    Grading by use
    
        
    static 30 · behavioural 50 · guidance 20
    
        
    
          Six probes drive the server for real, plus a second pass with the drafted
          recipe in front of the agent. Unmeasured layers are renormalised, never
          scored as zero, and a hard fail caps the total at 49 regardless of how
          well everything else went. Every run writes a transcript anyone can replay.
        
    
      
    
    
    

    
    
      Read bottom-up it is a grading service. Read top-down it is a refusal that gets
      progressively more expensive to make, which is why the cheapest layer is the one
      that says no most often.

    1 · intake
    
        
    A candidate arrives
    
        
    An MCP endpoint, a GitHub repo, or a skill file. The type is detected before anything is fetched.
    
      
    
      
    
        
    2 · free
    
        
    Fit review
    
        
    Do we already have this? Reads the roster above. A redundant candidate stops here and costs nothing.
    
      
    
      
    
        
    3 · paid
    
        
    Grade
    
        
    Only an MCP server, and only if fit passed. A repo has no tools to drive, so it is never sent.
    
      
    
      
    
        
    4 · human
    
        
    Approve
    
        
    The review lands as one note. Nothing auto-approves; a person flips one line.
    
      
    
      
    
        
    5 · scoped
    
        
    One agent
    
        
    The tool is granted to the subagent that needed it. The other twenty-six are unchanged.
    
      
    
    
    
  
    

    



    
  
    
    
    Do not take our word for it
    
    
    Check every grade on this page yourself
    
    
    
      “Replay the tape” is a slogan until someone can actually run it. This is
      the thing that runs it. One file, no dependencies, Node 18 or newer. It does
      not call our grader: it talks to the graded server directly, then checks our
      published claims against what it found.
    
    

    
    # Option 1: from the cloned repo
node mcp-scorecard/verify-tape.mjs https://webzum.com/api/mcp

# Option 2: or run directly without cloning
curl -sL https://raw.githubusercontent.com/clemenswan/clembot-doorman/main/mcp-scorecard/verify-tape.mjs | node - https://webzum.com/api/mcp
    

    
    
      That checks one grade. To check the whole chain instead, from a paid call to
      a completed audit,
      RUNBOOK.md
      is four ordered tests with the observed output of each. Three of them are free.
    
    

    
      
      
    • Fetches the server itself. Speaks MCP to the graded endpoint and reads its tools. We are not in this step.
      • 
      
    • Compares it to our tape. If we trimmed, altered or invented a tool description, this disagrees.
      • 
      
    • Re-runs the patterns from a copy inside that one file, over text it fetched from the server, not from us.
      • 
      
    • Checks the grade follows its own rules. A hard hit must cap at F. Steering must not.
      • 
    
    

    
    
      It reports a changed description as drift, not as fraud, because a
      server is allowed to change and only its operator knows which happened. The
      audit timestamp is printed so you can judge. A real disagreement is a bug
      report against us, and we would like to receive it.
    
    
    
    
      Pointing an agent at this is the same job: give it the transcript url and
      the four checks above. The transcript is newline-delimited JSON, public,
      unauthenticated, and never truncated or sampled. Everything a grade asserts
      is in it.
    
    
  
    

    



    
  
    
    
    Why it is scoped, not shared
    
    
    A tool given to every agent costs every agent
    
    
    
      Tool definitions are context. Load a twelve-tool server into every subagent
      and each one carries twelve descriptions it will mostly never call, plus
      twelve more chances to pick the wrong one. Logical grouping is not tidiness.
      It is the thing that keeps a subagent both cheap and correct.
    
    
    
    
      
    
        
    1agent
    
        
    Scoped, not shared
    
        
    The graded server is added for the subagent that needed it. The others are unchanged, so their context and their tool-selection odds are unchanged too.
    
      
    
      
    
        
    50of the grade
    
        
    Graded by use
    
        
    Half the score comes from driving the server with a real agent at temperature 0, three runs per probe. Reading a manifest cannot produce that half.
    
      
    
      
    
        
    1MCP tool
    
        
    The doorman is small
    
        
    The agent that decides what to trust holds Read and one MCP tool. It must not carry capabilities an untrusted server could talk it into using.
    
      
    
    
    
  
    

    



    
  
    
    
    Paid, per grade
    
    
    Agentified through Bazantic
    
    
    
      Grading a server costs real model tokens, so the scorecard is a paid API rather
      than a free one. Bazantic is the layer that makes it callable by an agent and
      payable per call, which is what lets the doorman buy exactly one grade with no
      subscription, no seat, and no human in the loop.
    
    

    
    
      
    
        
    Gateway and payments
    
        
        
    Bazantic
    
        Gateway live
      
    
      
    
        
      
          
    • 
            The import surface is live. The scorecard serves an OpenAPI 3.1 spec
            at /openapi.json, written for a machine reader that has never
            seen the service: every field says what it means and what a caller should do
            with it. A gateway is registered from exactly that URL, so this half needs no
            new code.
          
      • 
          
    • 
            The gateway owns settlement, and that is the point. Our x402 challenge
            is real and spec-correct, and it refuses a payment signature rather
            than pretending to verify one, because settlement is the single thing this
            service cannot check. The gateway provisions that pathway in front of it, and
            as of 2026-09-08 it exists: clembot-doorman.bazgateway.com, one
            cent for a grade on Base mainnet, free for every read. The flow above demonstrates
            both the paid path (settled on Base mainnet with an EIP-712 permit)
            and the free discovery path for cached audits.
          
      • 
          
    • 
            A Recipe is one tool, not a pipeline. Typed inputs, a prompt, a model
            and a bound tool set, published as a single MCP tool. So vetting becomes one
            call any agent can make. Grading is asynchronous, so that call returns a
            cached grade instantly or an audit id and a transcripts url. It never returns
            a provisional score to fill the silence.
          
      • 
          
    • 
            And a Recipe is itself an ungraded MCP surface. A published Recipe is
            one tool whose behaviour is a prompt the caller never reads, which is the
            shape of the finding at the top of this page, one layer up. Bazantic is also
            the first surface where that is fixable: the definition and the whole tool
            inventory are readable before a call, so the static probes can run over them
            without spending anything.

    Install and use it
    
    
    # 1. the CLI, once
npm i -g @bazantic/cli
baz login

# 2. register the scorecard. Its OpenAPI 3.1 spec is already
#    served, so there is nothing to write for this step.
API=https://scorecard.wanessalabs.com
baz gateway add --endpoint $API --spec-url $API/openapi.json \
  --auth-type api-key \
  --name "Doorman" --status active --json

# 3. a capped, revocable grant for the doorman to spend from.
#    --source hosted is not optional: without it a missing device
#    key falls back to your self-custody wallet, which is uncapped
#    and irrevocable. Bazantic documents this. The doorman refuses it.
#    The gateway URL is a SUBDOMAIN. Read endpointUrl out of
#    baz gateway list --json; never assemble bazgateway.com/<slug>.
baz grant create --name doorman --cap 5 --service clembot-doorman
baz curl https://clembot-doorman.bazgateway.com/grade \
  --account doorman --max-amount 0.05 --source hosted --json

# 4. the Recipe is DASHBOARD-ONLY: `baz recipe` does not exist in the
#    released CLI 0.8.0, though the docs describe it. Verified 2026-09-08.

      2026-09-08, and steps 1 and 2 were run: the gateway they produce is the live one.
      Step 3 configures the capped grant provisioning: the gateway enforces a $5 spend ceiling with a $0.05 per-call authorization. The
      dashboard's own connection test fails against this API with a 400, because
      POST /grade requires a body naming a server; the CLI path above

    What happens if you skip all of that
    
    
    A gate that fails closed
    
    
    
      Until a server has been graded and scoped, no subagent reaches it. The hook
      runs before every MCP tool call, reads a local file, and blocks anything it
      cannot vouch for.
    
    

    
    
      
    claude code · PreToolUse · matcher mcp__.*
    

    > research-agent: summarise what acme-helper knows about this repo

· calling mcp__acme_helper__search
BLOCKED by doorman

  doorman: 'acme_helper' is UNKNOWN. Blocking until it has been graded.

  An ungraded MCP server is not a trusted one. Nothing about
  'mcp__acme_helper__search' has been verified: not its tool
  descriptions, not its error handling, not whether its descriptions
  contain instructions aimed at you.

  To grade it:   /vet <server-url>

    
    
    

    
    
      
    No network
    
      
    The gate contains no network command at all. A gate that asks a server for permission is offline the moment the network is, and offline would have to mean allow.
    
      
    No dependencies
    
      
    Bash builtins and coreutils only. No jq, no node, no python. A gate that fails to start is a gate that fails open.
    
      
    Fails closed
    
      
    Unparseable input, missing registry, unknown server, unreadable file: all block. The default answer is no.
    
      
    Exit 2, never exit 1
    
      
    Only exit 2 blocks a tool call. Exit 1 is treated as a script error and the call proceeds. Every refusal path exits 2, and a test asserts the file contains no exit 1.
    
      
    Humans own the list
    
      
    Nothing writes to the allowlist automatically. The poller reports what changed and refuses to allowlist a hard fail even when the service says allow.
    
    
    
  
    

    



    
  
    
    
    
      
    The part most demos leave out
    
      
    What this refuses to do
    
      
    
        A grading service is only worth anything if it will tell you it does not
        know. Every line below is a place where producing a confident number was
        easy and we did not, and each one has a test that fails if the refusal is
        removed.
      
    

      
    
        
    
          
    It will not invent a grade
    
          
    
            No API key means the model probes do not run, and the run stops and
            says so. 70 of the 100 points on every grade on this page are
            unmeasured, the weights renormalise over what did run, and each
            report states it in its own provenance section. The injection scan
            needs no model, which is why the F is real.
          
    
        
    
        
    
          
    An unmeasured layer is not a zero
    
          
    
            Scoring a layer that did not run as 0 would drag every honest partial
            audit into a failing band. That is lying with arithmetic. The weight
            is removed instead and the other layers renormalise.
          
    
        
    
        
    
          
    An unknown price is not a free one
    
          
    
            The doorman asks what a grade costs and refuses to spend when the
            answer cannot be read. A client that defaults an unknown price to
            zero passes every spend cap it has, forever.
          
    
        
    
        
    
          
    It will not accept a payment it cannot verify
    
          
    
            The x402 challenge is real. Settlement is not wired, so a request
            arriving with a payment is refused rather than honoured. A paywall
            that opens for any string is worse than no paywall, because it looks
            like protection.
          
    
        
    
        
    
          
    It will not claim a capability to buy back a point
    
          
    
            The scorecard graded itself, scored a B, and fixed two real defects.
            It declined to fix the third: we will not advertise a protocol
            capability we have not implemented in order to raise our own score.
          
    
        
    
        
    
          
    The anchor says it is a stub
    
          
    
            On-chain anchoring returns anchored: false and a null
            transaction, deliberately, so nothing downstream can mistake it for
            a receipt that exists.

    Run it yourself
    
    
    The answer depends on your stack, so run it on yours
    
    
    
      A central benchmark tells you whether a tool helped somebody else's
      agent. Whether it helps yours depends on your harness, your model, and what
      your agents actually do. So doorman is a thing you install, not a service you
      ask. It runs on your machine, drives the agent you already use, spends from
      your own account, and the report is about your build.
      Nothing runs on ours and nothing is sent to us.

    Your key, your machine
    
        
    
          The credential your harness already uses is passed straight into a local
          container. It is never written to a file, never logged, and never leaves
          your machine except to the provider you already pay. There is no account
          here to make.
        
    
      
    
      
    
        
    The bill is bounded before it starts
    
        
    
          An agent loop resends the whole conversation every turn, so cost grows with
          the square of the turn count. --max-cost is the input and the
          turn cap is derived from it, so a ceiling of $2 is a ceiling of $2.
          --estimate shows the worst case and spends nothing.
        
    
      
    
      
    
        
    Free layers first
    
        
    
          doorman doctor and doorman report need no model at all.
          Most of what you want to know about a server, including whether its tool
          descriptions are giving your agent orders, costs nothing to find out.
        
    
      
    
      
    
        
    It drives your harness
    
        
    
          --agent claude-code runs the agent you already run. An adapter that
          cannot measure something reports it as not measured rather than
          estimating it, so the columns you get are the ones that are real.
