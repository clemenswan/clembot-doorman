Payment & Custody Architecture

Why the AI Agent Never Holds a Crypto Wallet

Decoupling intent from custody: Clembot Doorman coordinates x402 micropayments on Base without exposing private keys to agent context, without requiring wallet SDKs, and with deterministic offline spend caps.

1. Custody Decoupling

The Anti-Pattern We Refuse

Putting private keys into an LLM's prompt context is an extreme security hazard. Indirect prompt injection or runaway agent loops could exfiltrate the key or drain funds. Doorman structurally bans self-custody wallets in agent memory.

2. Scoped Facilitation

Bazantic Hosted Grants & EIP-712

Developers configure a scoped, revocable grant (baz grant create --name doorman --cap 1 --service <slug>) or single-use EIP-712 permit. The agent passes an ephemeral credential; Bazantic's facilitator settles on Base (eip155:8453 USDC).

3. Zero Package Bloat

Standard HTTP & MCP, Not an SDK

No npm install bazantic or web3 SDKs required. The gateway communicates via standard HTTP 402 Payment Required (RFC x402 v2 headers) and Model Context Protocol (MCP) over SSE. Native Node.js fetch handles everything.

4. Local Spend Ledger

Free Reads First ($0.00) & Hard Caps

Doorman's local budget.mjs checks and reserves $0.01 in an offline append-only ledger (ledger.jsonl) against $1/run and $5/day caps. Phase 1 Fit Review stops redundant tools at $0.00, and all cached reads are 100% free.

Evidence & Deep-Dive Details

Frequently Asked Architecture Questions

How does an agent actually pay without private keys?

The agent acts as the requester, not the custodian. When calling a paid audit route (POST /grade), the Bazantic Gateway issues an RFC x402 HTTP 402 challenge specifying the exact amount (10,000 atomic units = $0.01 USDC) and Base contract address.

The agent satisfies this with a developer-provisioned Bazantic grant token or single-use EIP-712 spend permit. The Bazantic edge gateway facilitator settles the transaction against the developer's prefunded balance on Base mainnet. The model never holds a seed phrase, private key, or signing authority.

Do I need to install Bazantic in my project dependencies?

No. Clembot Doorman has zero runtime dependencies. Bazantic is an infrastructure gateway (hosted at clembot-doorman.bazgateway.com), not a client library. It speaks standard HTTP status codes, standard JSON bodies, and standard MCP over Server-Sent Events (SSE). Any HTTP client or standard agent harness connects natively.

How does the 2-Phase Funnel prevent runaway agent spend?

First, Phase 1 Local Fit Review compares the candidate against your existing tools and skills. If your roster already handles the task, the verdict is REDUNDANT and the run terminates before constructing the network client ($0.00 spent).

Second, cached reads are permanently free. Querying getLatestGrade, getAudit, or /feed costs $0.00.

Third, if a paid audit is required, budget.mjs reserves the $0.01 against your configured spend caps ($1.00/run, $5.00/day) in an offline append-only ledger (.claude/registry/ledger.jsonl) before the request fires. If the request fails, the reservation is released.

How does the offline gate enforce security in < 5ms?

The security gate (mcp-gate.sh) is a standalone 180-line Bash hook wired to Claude Code's PreToolUse event. It intercepts every tool invocation matching mcp__.*, extracts the server name, and checks registry/allowlist.json locally. If unapproved or denied, it exits 2 in under 5ms, halting execution before any payload reaches the model's context.
